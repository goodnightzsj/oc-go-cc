## Design Context

### Users

Developers and operators running routatic-proxy locally or on a small server. They use the console repeatedly to confirm proxy health, inspect individual requests, understand token and cost trends, and diagnose routing or provider failures without leaving their coding workflow.

### Brand Personality

Calm, precise, trustworthy. The interface should feel like a focused operational instrument: technically capable without looking noisy, playful, or promotional.

### Aesthetic Direction

The user requested a complete seven-page redesign on 2026-09-11, referencing sub2api and new-api. Build a focused API management console: persistent desktop side navigation, a compact global toolbar, clearly separated KPI groups and chart surfaces, a filter-first log workspace, readable subscription summaries, and directly reachable provider configuration. Use a restrained indigo/slate palette with distinct light/dark surfaces, legible native system/CJK fonts, tabular numerals, and consistent 4px-based spacing. Keep the embedded HTML/CSS/JavaScript stack; use reference products for information architecture, not their code, branding, or backend. On mobile, adapt navigation and content priority rather than shrinking the desktop layout. Avoid decorative gradients, nested cards, excessive animation, fake chart values, and empty panels that imply no account usage.

### Design Principles

1. Make token, cost, latency, and failure definitions explicit and consistent across every view.
2. Optimize for fast scanning first, then progressive detail through keyboard-accessible interactions.
3. Use color to encode state and series, never as the only carrier of meaning.
4. Preserve focus, reduced-motion support, and readable contrast as baseline behavior.
5. Reuse the existing zero-dependency components before adding markup or JavaScript.
