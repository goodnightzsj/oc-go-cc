# OpenCode 历史恢复与保留策略

## 关闭自动清理

`storage.retention_days` 为负数（推荐 `-1`）时禁用请求历史清理；省略或设置为 `0` 仍使用默认 7 天，正整数为保留天数。仅修改该字段，保留其他配置；重启后以日志 `request retention cleanup disabled` 确认生效。此设置不删除或更改已有记录。

实现入口为 `internal/storage/retention.go`。旧版本把所有非正数当作 7 天，必须先部署包含禁用修复的版本再恢复历史。恢复后不要回滚到仍把负数当成 7 天的旧程序，否则启动清理可能再次删除历史。

## 已核实的最终同步方法

来源为本项目 Claude session `8ebffb0f-fb58-4290-b33e-b8345253d709.jsonl` 的 2026-09-04 11:19Z 完成记录（3062 行）及 14:25Z 文档更正（4450 行）；8 月旧方案不是最终方案。

- 在已有 Edge 登录态中获取 `usage.list` 的实际协议，逐页抓到明确空页，检查分页顺序、重复 ID 和首尾时间。发生请求错误或解析失败必须停止，不能把错误当成分页终点。
- 原始 `inputTokens` 与 `cacheReadTokens` 分开保存，不使用页面四舍五入后的合计数。缓存写入、推理等字段按实际响应保留；缺失字段不能凭空补造。
- `cost` 的整数单位为 `1e-8 USD`，写入费用时直接除以 `1e8`，不先舍入到 6 位，也不再乘套餐倍率。
- 官方 `timeCreated` 是完成时刻，本地 `start_time` 是开始时刻；匹配需核对模型、Token 和实际完成时间。仅金额相等不足以证明同一请求。
- 官方导入行使用稳定官方 ID，归属 `opencode-go`，费用来源 `provider`。无法从备份唯一证实的状态、耗时、流式和路由信息应标记未知（`details_known=0`），不能伪装成成功请求。

历史 `oc_sync.py` 存在非事务 `INSERT OR REPLACE`、费用舍入和默认成功等行为；`scripts/platform_reconcile.py` 还有金额配对及固定模型写入。这些脚本可帮助理解旧协议，不应直接运行其写入模式恢复生产。

## 恢复与验证顺序

1. 核对服务实际数据库路径，独立备份当前配置与 SQLite，验证备份完整性；不要用旧库整体覆盖现库。
2. 对比官方最新导出、旧快照和全部相关备份。较新的备份也可能包含旧的错误 Token 口径或中间重复记录；保留原文件，先在副本演练。
3. 只恢复可证明的缺失记录，以唯一 ID 幂等导入，遇到歧义保留报告。使用事务和参数化 SQL，不删除未匹配的其他平台或当前请求。
4. 对账记录数、模型、纯输入、缓存读取/写入、输出、整数费用与时间；二次执行应零新增。验证真实历史接口和页面，不以健康检查代替数据验收。
