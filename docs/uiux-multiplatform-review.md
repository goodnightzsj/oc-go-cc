# 五平台部署后 UI/UX 与数据呈现评估

## 结论与边界

可以继续美化，优先级应是可操作性、信息层级、跨设备阅读，再是配色和细节；不需要更换前端框架或增加图表依赖。本轮只分析，没有修改产品视觉或交互行为。

评估对象为已部署的 `0b28ab2`，UI build `95403ba4a0a5`。2026-09-11 再次确认服务 `active/running`、`NRestarts=0`、`/health` 为 `ok`；已有生产冒烟为 210 项检查、29 个平台/页面组合、21 项布局检查。五平台的数据与配置实现见[适配记录](platform-integration-review.md)，真实账户权限缺口仍是[未完成任务](../.codex-tasks/20260910-platform-integration/tasks/08-account-validation/SPEC.md)，不能因页面渲染正确而结项。

本轮另运行真实 Go/SQLite 合成后端，对七页的 1440/390px 视图及五个平台套餐视图作只读观察，14 个页面视图、5 个套餐视图成功，0 脚本异常、0 越界请求。测试服务正常停止并 PASS。截图中的金额、模型与 Key 均为合成数据，不代表生产账户。

## 设计判断

**模板化检查：部分不通过。** 概览、历史和分析已有清楚的运营工具定位，没有营销式渐变大标题；但连续同权指标、Fallback/Settings 的多层灰框，以及性能表整片绿色，仍有模板化和视觉权重不均的问题。应保留现有紧凑布局、靛蓝强调色和原生 SVG，减少无意义容器，而不是换一套炫目风格。

已经做对的部分：

- 五个平台能独立选择，同名模型保留平台标识；费用来源、未知价格和本实例统计范围可见。
- 套餐页没有把 Go 的窗口强加给其他平台；OpenRouter 的账户余额、Key 限额、BYOK 与 AWS 的官方服务费用分开呈现。
- 页面导航有文字，历史明细有键盘入口，趋势图已有方向键定位和可切换图例，基础组件可以继续复用。

## 优先问题

### P1：补全键盘与辅助技术的操作合同

- **排序**：历史和性能表共 14 个排序表头都不是可聚焦按钮。实测性能 `Avg (ms)` 按 Enter 后 `aria-sort` 仍为 `none`，鼠标点击后变为 `descending`。根因见 `internal/gui/assets/index.html:213`、`:369` 与 `app.js:1098`、`:2550`。应在 `th` 内使用原生按钮，保持现有排序逻辑和 `aria-sort`；不要为排序引入另一套状态。
- **备用链**：条目 `draggable=true`、`tabIndex=-1`，仅有拖拽事件，无上移/下移入口。四个跨平台同名模型的删除按钮还都朗读为 `Remove shared-model`，不能辨别平台。根因见 `app.js:3043`、`:3047`、`:3056`。建议保留拖拽并增加有平台名称的上移、下移、删除按钮，复用原有链顺序。
- **设置开关**：代理服务、自启动、通知三个复选框的可访问名称为空，ARIA 快照只有无名 `checkbox`。见 `index.html:624`、`:635`、`:646`。将现有可见文字与控件关联，不能仅依赖文字邻近。
- **图表朗读**：方向键能移动游标，但 `aria-valuetext` 只有日期，例如 `09-06`，未包含当日 Token/费用。见 `app.js:2199`。建议让同一选中点的日期与数值共同成为可访问描述，保留可视 tooltip 和明细表。

验收：仅用 Tab、Enter、Space 即可排序、调整备用链和识别服务开关；同名模型能被平台区分；图表选点可取得日期与数值。以上是 DOM/交互层实证，尚未完成 VoiceOver/NVDA 真人测试。

### P1：历史页先呈现待排查请求，设置页先呈现目标平台

- 合成十条请求时，历史表距面板顶部约 **605px（桌面）/1358px（手机）**；手机首屏全是分布汇总，搜索和请求明细不在首屏。见 `index.html:136`、`:145`、`:157`。建议顺序为“标题与范围 → 搜索/主要筛选 → 紧凑摘要 → 请求表”，把分布详情放入默认折叠区或明细之后，保留 CSV 和高级筛选。
- 设置页默认展开 **53 个字段**，面板内容高约 **3782px/4087px**，可视高度仅 809px。五个平台和服务器配置全部串联，定位 CommandCode 或 OpenRouter 需要长距离滚动。见 `index.html:703`。建议按平台用原生 `details/summary` 分组，默认展示当前使用平台，超时和协议地址作为高级项；保存区显示变更数并保持可达。仍发送现有“只保存变更字段”的 patch，不改为覆盖整个配置。

验收：390px 下第一屏能进入请求搜索/明细；用户能直接定位任一平台；折叠、筛选、切页不丢未保存字段，不改变密钥脱敏和环境变量优先级。

### P2：统一字段含义与字体，降低比较成本

概览展示 6 个同权指标，分析展示 8 个，手机端分析成为长串单列指标；分析与套餐表头实测只有 **9px**。见 `index.html:74`、`:468`、`style.css:997`。建议首屏强调请求、Token、已知费用、成功/失败，缓存细分放到次级区；表格正文保持可读字号并使用等宽数字。不要因省空间删除未知记录数、币种、统计时间或成本来源。

`$1.50 + ?` 正确表达不完整合计，但可读性一般。建议主值使用“已知费用 $1.50”，紧邻“5 条价格未知”；展开后仍能看明细和来源。性能表建议明确“有效样本数”“成功率已知样本”以及 P50/P90/P99 定义，避免把单个样本的分位数理解为稳定性能结论。大面积绿色缩为小标签/单元强调，数值必须保持独立可读。

### P2：套餐页统一结构，不统一不相同的账单含义

保留“官方数据”和“本实例账本”两层，页面名称可改为“用量与账单”。来源、时间、币种、账户能力状态放在紧凑状态栏；长端点放进可展开的来源详情。官方入口降为次级链接，刷新保留主操作。当前 OpenRouter Key 卡片左侧只有 Key 提示却占较大面积，宜把 Key 标题放到明细上方。

| 平台 | 应突出的官方内容 | 不能通过美化抹掉的边界 |
| --- | --- | --- |
| OpenCode Go | 最紧窗口、剩余比例、重置时间；其它窗口用紧凑进度条 | 美元由套餐规则换算；本地模型费用不是官方账单；现用账户接口返回 403 时不展示成功额度 |
| OpenCode Zen | 账户数据不可获取的原因与官方控制台入口 | 未找到公开账户接口合同；本实例消费不能冒充账户余额 |
| AWS Bedrock | 服务费用、币种、完整 UTC 日期、Estimated、缓存时间 | 不是余额；独立 IAM、显式账户、收费手动查询；普通刷新不得触发收费 |
| OpenRouter | Management Key 账户余额、每 Key 限额、BYOK 分列 | 不合计多 Key；保留负余额与单 Key 错误；不假定管理 Key 与推理 Key 属于同一账户 |
| CommandCode | 原生推理接入状态与官方 Usage/Billing 入口 | 公开推理 API 不等于公开余额 API；本地账本只覆盖本实例记录 |

验收：用户可以清楚回答“哪个平台、什么范围、什么来源、更新时间、能否视作官方余额”；403、部分 Key 失败、未配置、未公开接口各有明确的下一步。

### P2：补齐跨设备、双主题与文案一致性

- 390px 下多数刷新/保存按钮约 32px 高，下拉触发器约 34px；备用链删除按钮宽约 18px。建议粗指针环境扩大操作区至约 44px，保留桌面紧凑密度。这是设计目标，不能仅凭尺寸就宣称违反某项可访问性标准；脚本记录中的 2px 原生 select 是自定义控件的隐藏源，不算真实触摸目标。
- 切换系统深/浅色后，body 背景都为 `rgb(17, 19, 21)`，文本都为 `rgb(243, 244, 246)`。目前不能宣称已完成双主题。见 `style.css:319` 和页面大量固定色类；应复用并补全现有颜色变量，再适配浅色，而不是直接反色。
- 中文切换后 `html.lang=zh` 正确，但前四个平台仍出现 `Timeout (ms)`、`Stream Timeout (ms)`，CommandCode 则是中文；这些行为说明应统一翻译。URL、API Key、协议字段本身保留原文。见 `index.html:735`、`:739`、`:785`。
- 手机导航可横向滚动，页面没有整体横溢出；仍建议提供更清楚的可滚动提示与选中页可见性，不把页面整体不溢出等同于手机体验优秀。

## 七页改进清单

| 页面 | 核心任务 | 建议的数据与布局顺序 | 保留内容 |
| --- | --- | --- | --- |
| Overview / 概览 | 快速判断代理是否健康、哪个平台异常 | 平台/时间/状态 → 4 个关键指标 → 请求趋势 → Token/缓存细分 → 平台分布 | 实例范围说明、未知费用数、平台隔离；趋势不用装饰性曲线 |
| History / 历史 | 找到并解释单次请求 | 搜索和平台/时间 → 紧凑摘要 → 明细表 → 按需分布 | 全部筛选、CSV、请求详情、成本来源、完整模型/平台身份 |
| Performance / 性能 | 找出慢或不稳定的模型 | 标题/有效样本口径 → 平台/时间 → 可键盘排序的表 → 低样本说明 | P50/P90/P99、平均值和成功率的不同含义；不把未知当失败 |
| Fallback / 备用链 | 理解并修改场景路由顺序 | 当前场景与主模型 → 带序号的备用顺序 → 预览/变更状态/保存 | 跨平台标识、已有预览与保存；键盘上移/下移与拖拽等价 |
| Analytics / 分析 | 比较时间趋势与成本构成 | 平台/UTC 日期 → 关键摘要 → 时间明细 → 按需缓存及分布 | 已有原生 SVG/表格、币种、日期粒度、未定价范围；不强加重复图表 |
| Quota / 套餐 | 理解官方额度、消费与本地差异 | 平台/能力状态 → 官方数据 → 本实例账本 → 来源详情 | 每个平台特有口径、AWS 收费告知、Key 错误与未知状态 |
| Settings / 设置 | 安全地修改一个平台 | 运行状态 → 平台定位/折叠组 → 基本字段 → 高级配置 → 变更保存区 | 所有已支持字段、独立 Key、部分 patch、校验、脱敏导出 |

## 设计健康评分

这是基于当前页面的人工启发式评分，不是自动测试覆盖率或可访问性认证。

| 启发式 | 分数（0–4） | 主要依据 |
| --- | --- | --- |
| 系统状态可见 | 3 | 服务/账户状态清楚；还可统一刷新和缓存时间 |
| 符合真实概念 | 3 | 来源和余额区分正确；Quota 名称覆盖多个不同概念 |
| 用户控制 | 2 | 有筛选重置；排序和链调整欠缺键盘等价方式 |
| 一致性 | 2 | 新旧页面容器、字号、语言和主题行为有差异 |
| 错误预防 | 3 | AWS 显式收费操作、密钥脱敏和字段校验已存在 |
| 识别而非记忆 | 2 | 所需平台配置藏在长表单中，部分操作名称不完整 |
| 使用效率 | 2 | 有命令面板/搜索；历史明细首屏效率低 |
| 简洁和视觉层级 | 2 | 大量同权指标、长灰框和小字增加扫描成本 |
| 错误恢复 | 2 | 能区分错误原因，但多数尚需手动跳转设置定位 |
| 帮助和解释 | 3 | 套餐/成本来源说明充分；性能术语可更贴近数据 |
| **合计** | **24/40** | **基础可用，需要重点改善可用性与层级** |

认知负荷八项检查：主任务聚焦、信息分块、视觉层级、逐步披露四项失败；关联分组、单一操作、选择清晰、上下文保持四项通过。失败集中在历史和设置，属于高负荷区域，不意味着所有页面都难用。导航虽有七页，但标签固定且领域明确，不建议只为凑数量强行合并页面。

## 使用者走查

- **Alex（高频用户）**：为查一条失败请求，手机先经过模型/平台分布，再见搜索和明细；历史优先级应该反过来。已有搜索快捷键保留，不再新增一套导航框架。
- **Sam（键盘/辅助技术用户）**：能切换页签和图例，但不能用普通焦点顺序排序表头、调整备用链；三个无名开关和同名删除操作难以辨别。需先补原生语义，再谈美化。
- **Casey（手机用户）**：历史表从 1358px 才开始，分析指标逐条堆叠，备用链删除区域狭窄。应针对手机重排信息，不只是把桌面列压成单列。
- **本项目运维值守者**：需要同时判断服务健康、平台权限与官方账单是否可信。当前来源说明是优势；应将“未配置→对应平台设置”“上游403→官方权限核对”做成明确路径，不能用统一绿色成功卡片替代能力差异。

## 后续实施顺序（待用户确认）

1. 用 `harden` 处理上述 P1 键盘/名称/状态问题，复用原生按钮和现有状态；定向 DOM/键盘回归先行。
2. 用 `arrange`、`adapt` 重排历史与设置、优化手机触摸区；保持五平台字段和筛选合同不变。
3. 用 `clarify`、`typeset` 统一来源说明、未知费用、超时术语和表格字号；用 `normalize` 补全主题变量。
4. 最后 `polish` 统一边界、间距和状态反馈；重新验证五平台矩阵与关键失败路径。

建议默认先处理 P1，再做视觉统一。实施前只需确认：是否按这个顺序推进，以及浅色主题是否纳入同一轮。此次未执行这些后续技能或改动。
